# پزشک‌یار Production

نسخه واقعی سامانه نوبت‌دهی و پرونده پزشکی با Node.js + Express + PostgreSQL.

## امکانات
- ورود نقش‌محور مدیر، پزشک و منشی
- بخش مدیر از رابط عمومی مخفی است و فقط از مسیر `/admin-login` در دسترس است
- نوبت‌دهی آنلاین و نوبت‌دهی مستقیم منشی
- تعریف روزهای ویزیت و ساعات قابل رزرو
- ایجاد خودکار پرونده پزشکی هنگام ثبت بیمار
- جستجوی بیمار با نام، کد ملی، شماره پرونده و موبایل
- ثبت ویزیت، تشخیص، توضیحات، علائم حیاتی و نسخه با تاریخ
- تایم‌لاین کامل ویزیت‌ها
- بارگذاری عکس، اسکن مدارک و PDF و نگهداری متادیتای آنها
- خروجی Excel
- پشتیبان‌گیری واقعی سطح برنامه از داده‌های PostgreSQL و فایل‌های پرونده در ZIP
- اجرای خودکار Backup طبق `BACKUP_INTERVAL_HOURS`
- Helmet، Rate Limit، Session امن و محدودیت حجم آپلود
- آماده برای Render + PostgreSQL

## راه‌اندازی محلی
1. PostgreSQL بسازید.
2. `.env.example` را به `.env` تبدیل و مقادیر را تنظیم کنید.
3. `npm install`
4. `npm start`
5. مرورگر: `http://localhost:3000`

## ورود اولیه
مدیر از `ADMIN_EMAIL` و `ADMIN_PASSWORD` ساخته می‌شود. رمز را در `.env` نگه دارید و عمومی نکنید.

## Render
`render.yaml` برای Web Service + PostgreSQL آماده شده است.
نکته مهم: دیسک محلی Render برای فایل‌های آپلودی و Backup دائمی نیست. برای استفاده واقعی از اسناد پزشکی باید دیسک پایدار یا Object Storage/S3-compatible متصل شود و Backupها خارج از Web Service نگهداری شوند.

## Backup
از پنل مدیر می‌توان ZIP و Excel گرفت. ZIP شامل JSON داده‌های پایگاه‌داده و فایل‌های پرونده است. برای بازیابی کامل، `src/restore.js` را روی یک محیط امن با همان دیتابیس اجرا کنید.

این پروژه نمونه آماده است و قبل از استفاده واقعی با اطلاعات پزشکی باید سیاست دسترسی، نگهداری داده، رمزنگاری در حالت سکون، MFA و الزامات قانونی محل فعالیت خود را نیز بررسی کنید.

## اشتراک و پارسیان
- فروش اشتراک به پزشکان و ثبت اشتراک دستی/رایگان/آنلاین.
- فهرست پزشکان با تخصص، آدرس و نوع بیمه.
- پنل ورود اطلاعات پذیرندگی پارسیان بدون کدنویسی.
- نوبت آنلاین با وضعیت پرداخت؛ پرداخت‌نشده با وضعیت `unpaid` و رنگ نارنجی در فهرست نوبت‌ها باقی می‌ماند.
- اتصال تراکنش واقعی پارسیان نیازمند API رسمی و مشخصات قرارداد PSP است؛ این نسخه محل تنظیم پذیرندگی و چرخه وضعیت پرداخت را فراهم می‌کند و بدون API رسمی ادعای تراکنش واقعی نمی‌کند.

## پرداخت واقعی پارسیان
این نسخه چرخه واقعی IPG پارسیان را با درخواست Sale، انتقال به NewIPG، Callback، VerifyPayment و ConfirmPayment پیاده‌سازی می‌کند. هر مدیر یا پزشک می‌تواند PIN/اطلاعات پذیرندگی خود را از پنل وارد کند؛ مشخصات واقعی پذیرنده باید از تجارت الکترونیکی پارسیان دریافت شده باشد. مبالغ و شناسه تراکنش‌ها در جدول payment_transactions ذخیره می‌شوند. مستندات/نمونه‌های عمومی وب، endpointهای Sale/Confirm پارسیان را نشان می‌دهند. citeturn1search0turn1search5

## پنل واحد پذیرندگی
در رابط کاربری فقط یک پنل «تنظیمات پرداخت پارسیان» وجود دارد. مدیر یا پزشک وارد همان پنل می‌شود و PIN/شناسه پذیرنده، اطلاعات لازم و Callback را وارد می‌کند. سرویس پرداخت از همین رکورد برای Sale/Callback/Verify/Confirm استفاده می‌کند.

## احراز هویت Production
- ورود از `/api/auth/login` برای مدیر، پزشک و منشی.
- نقش کاربر در PostgreSQL ذخیره می‌شود و Backend هر مسیر حساس را با middleware نقش کنترل می‌کند.
- رمزها با bcrypt hash می‌شوند و در GitHub ذخیره نمی‌شوند.
- `ADMIN_EMAIL` و `ADMIN_PASSWORD` باید فقط در Environment/Secret سرویس Production قرار گیرند.
